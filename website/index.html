Architecture

Calibre's Q-UTXO state model treats the transaction — not the account — as the atomic unit of money. Every unit of value is an unspent output cryptographically bound to a post-quantum lock.

Quantum-UTXO

State is a map from UTXO ID to (value, lock). No accounts, no nonces. Conflicts between transactions are syntactic, checkable in microseconds.

Four verification gates

Mempool conflict tags. State existence. Runtime lock binding. Cryptographic signature. Each gate rejects a distinct attack class.

Real ML-DSA-44

1,312-byte public keys, 2,420-byte signatures, verified on every spend by dilithium-rs inside the WASM runtime.

Forkless migration

The QuantumLock enum allows governance-driven cryptographic change without a chain fork. Pure-PQ today, hybrid classical+PQ whenever needed.

What is proven, not claimed

  • Forgery rejection. A random 2,420-byte signature is accepted by the mempool (which does not verify crypto) and rejected at block execution. The UTXO set is unchanged.
  • Double-spend rejection. Two conflicting transactions submitted in parallel: one wins, the other is rejected with Priority is too low.
  • Replay rejection. Re-submitting a spend after inclusion returns Transaction is outdated — without consuming block space.
  • Conservation of mass. Every spend satisfies Σ inputs ≥ Σ outputs. Issuance is not affected by transfers.
  • Named testnet. Chain ID calibre_testnet_1, SHA-256 fingerprint 7b7ba4d1....

Run it in 30 seconds

Prerequisite: Docker.

git clone https://github.com/calibre-protocol/calibre-template
cd calibre-template
docker compose up

# In another terminal:
docker compose exec node pq-signer keygen > pubkey.txt
curl -X POST http://127.0.0.1:8090/faucet \
  -H 'Content-Type: application/json' \
  -d "{\"pubkey\": \"$(cat pubkey.txt)\"}"

# You now hold 1,000,000,000 testnet CAL, cryptographically
# bound to a Dilithium public key only your private key can spend.
