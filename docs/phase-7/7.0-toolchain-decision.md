# Phase 7.0 — ZK Toolchain Decision

**Decision:** Use **RISC Zero v3.0.6** for Calibre's light-node state proofs.

**Date:** 2026-09-21
**Session:** Phase 7.0

## Context

Phase 7 requires recursive ZK proofs over a Merkle commitment to the UTXO
set. The toolchain must support:
- Rust-native circuits (no DSLs)
- Recursive proof composition (IVC)
- Mobile-verifiable proofs
- Production-grade stability

## Options evaluated

### SP1 (Succinct)
- **v6.8.0**: `TempDir::keep` method doesn't exist — release regression
- **v6.0.2**: Version skew — `sp1-sdk 6.0.2` cannot construct `BasefoldProof 6.8.0`
- **v6.1.0**: `sp1-zkvm` pulls networking crates (`mio`, `socket2`) into the RISC-V circuit — fundamental dependency bug
- **Soundness:** CVE in recursive verifier for v6.0.0–v6.0.2
- **Production light clients:** None

### RISC Zero v3.0.6
- **Build:** Clean compilation on first complete attempt
- **Prove + verify:** Working — verified STARK on this machine
- **Production light clients:** Helios (Ethereum, audited by zkSecurity),
  Blobstream Zero (Celestia), Anoma Resource Machine
- **Maturity:** 82 releases, 25 stable versions
- **Toolchain:** `rzup install` — no dependency conflicts

## Decision

RISC Zero. The production light-client precedent and the clean build are
decisive. SP1 v6.x is not production-ready for the recursive-proof use
case Phase 7 requires.

## Reproducibility

    curl -L https://risczero.com/install | bash
    source ~/.bashrc
    rzup install
    cargo risczero new --guest-name method calibre-zk-hello
    cd calibre-zk-hello
    cargo run --release

Expected output:
    Guest result: 10
    ✅ Verification: OK
