THE HARD PART

The math that makes post-quantum hard.

Replacing elliptic-curve cryptography with lattice cryptography is not a one-line code change. The signatures are roughly 35× larger. Every existing blockchain was designed around 100-byte signatures. This is why the migration has not happened yet.

ARCHITECTURE

Five layers, one invariant.

Every unit of value is an unspent output bound to a post-quantum lock. No accounts. No nonces. No elliptic curves in the value path.

Key design choice: Calibre uses UTXO rather than an account model because UTXO conflicts are syntactic — two transactions conflict if and only if they share an input. That makes mempool-level double-spend rejection and parallel verification possible.
THE SOLUTION

How Calibre recovers throughput.

We cannot shrink the signatures — FIPS 204 defines their size. What we can do is change the architecture so that large signatures don't dominate cost. Calibre uses four independent techniques.

01

UTXO aggregation

In an account model, every spend generates its own signature. In a UTXO model, ten inputs can be combined into a single transaction with one signature.

10 UTXOs → 1 signature
02

Mempool-level conflict detection

Non-conflicting transactions are verified in parallel. The mempool knows syntactically that Tx-A and Tx-B don't touch the same UTXO — no sequential execution required.

Parallel verification
03

Fast-Path settlement

Transactions with no conflicting inputs broadcast and settle immediately, without waiting for block production. A 6-second block time becomes the worst case, not the typical case.

Sub-second for non-conflicting
04

Lattice signature aggregation (roadmap)

Multiple Dilithium signatures can be combined into a single composite proof using BLS-style aggregation adapted for lattices. This is an active area of cryptography research.

Under research

Why this works: the throughput math

Naive PQC on Bitcoin
  • 1 MB block limit
  • Each tx: ~4,000 bytes
  • ~250 tx per block
  • 10 min block time
  • ≈ 0.4 TPS
Calibre
  • Substrate block limits (dynamic)
  • Each tx: ~4,000 bytes, but aggregated
  • Parallel verification of non-conflicting
  • 6s block time
  • ≈ 100+ TPS base, scaling with inputs

Throughput is bounded by bandwidth, not cryptography. Multi-core CPUs verify hundreds of Dilithium signatures per second; the bottleneck is how fast the network can gossip the bytes. UTXO aggregation reduces the number of signatures required for the same economic activity.

THE LANDSCAPE

How the big chains are handling quantum.

Every serious blockchain knows about the quantum threat. Each is solving it differently — and each solution has a cost. Here is the honest comparison, based on public research and proposals.

₿

Bitcoin

Post-quantum research · no deployment

The problem: ECDSA exposes the public key whenever a UTXO is spent. A quantum computer has ~10 minutes (one block) to derive the private key and front-run the transaction.

Proposed solution: BIP-360 / P2MR introduces post-quantum script opcodes. Users would voluntarily migrate to new addresses.

The cost: Soft fork required (years of political coordination). Users must move funds. Signature sizes explode — 1 MB blocks fit far fewer transactions.

Ξ

Ethereum

Account abstraction · research phase

The problem: Beacon Chain consensus relies on BLS12-381 elliptic curves. A quantum computer breaks both the signature scheme and the consensus layer simultaneously.

Proposed solution: ERC-4337 account abstraction. Wallet contracts become programmable — cryptography can be swapped at the application layer.

The cost: Every user must deploy a new wallet. ~3.3 KB signatures cost ~70,000 gas — unaffordable for most users without L2 rollup compression.

Σ

Solana

Early research · no public roadmap

The problem: Ed25519 in the critical path of every transaction. Solana's throughput depends on parallel signature verification at the TU (Transaction Unit) level.

Direction: Falcon-512 is the most discussed candidate — smaller than Dilithium but harder to implement side-channel-resistant.

The cost: Unknown. Solana's block model assumes compact signatures. Redesigning around 1.5 KB signatures may require a hard fork.

⚛

QRL

Post-quantum from genesis · account model

Already solved: Quantum Resistant Ledger has been using XMSS hash-based signatures since 2016. It is genuinely quantum-safe today.

How it works: XMSS one-time signatures. Fast verification, hash-based security, well-studied.

The cost: Account model — no UTXO parallelism, no mempool conflict detection. XMSS keys are stateful: each key can sign only once before needing rotation, a UX burden most users ignore.

◆

Calibre

PQ-first L1 · UTXO model · shipped

Design starting point: What if we assume signatures will be 35× larger and build the chain around that constraint from day one?

Our approach: Q-UTXO state model + FIPS 204 ML-DSA-44 verification inside WASM + four-gate verification + Fast-Path mempool + UTXO aggregation for parallel verification.

Trade-offs we accept: Larger witness data per transaction. Higher storage per UTXO. Node operators need modern hardware. In exchange: quantum safety is native, not bolted on.

The pattern: legacy chains retrofit post-quantum security onto architectures that were never designed for it. Calibre was designed PQ-first. This is the same difference as adding electric motors to a Model T versus designing an electric car from scratch.

THE VISION

What Calibre becomes.

The testnet today is a working prototype. The destination is a full post-quantum cryptoeconomy — a monetary system designed from the first line of code for a world where elliptic curves no longer protect value.

The money layer of the post-quantum internet

When quantum computers break ECDSA — and they will — trillions in existing digital assets become drainable. The chains that survive will be the ones already running post-quantum signatures at the protocol layer. Calibre is designed to be one of them.

A seedless, hardware-attested wallet

The A.E.G.I.S. design eliminates the twelve-word seed phrase entirely. Your biometrics, your device's secure enclave, and a threshold of trusted hardware become the key. Lose your phone, recover via social threshold — not via a piece of paper under your mattress.

Trustless cross-chain value movement

The ZK Intent Bridge replaces multi-sig bridges with a solver network and zero-knowledge proofs. Cross-chain swaps settle in blocks, not in trust assumptions. No wrapped tokens, no custodian honeypot, no $2.5B drains.

Privacy that doesn't cost throughput

ZkShield UTXOs are opt-in. Shielded transactions use Pedersen commitments and nullifier sets. Users choose: transparent post-quantum or shielded post-quantum — on the same chain, at the same throughput.

A monetary system that migrates with cryptography

When the next generation of post-quantum primitives is standardized — and it will be, in 5, 10, 15 years — Calibre upgrades by governance vote, not by hard fork. The QuantumLock enum and the Substrate runtime make cryptographic migration a routine operation.

An open protocol, not a product

GPL-3.0-only. Auditable. Forkable. Anyone can inspect, fork, or contribute. The value is not in the code — the code is public. The value is in the network, the team, and the discipline of shipping verifiable claims.

Calibre Protocol is the money we would build if we started in 2050 and worked backwards.

The quantum transition is not a question of if.

Only of when — and whether the money we build will survive it.
